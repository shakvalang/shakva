# Bootstrapping Shakva

The goal is to run a compiler written in Shakva on Sylva and use it to rebuild itself from source.

The proposed stage0 is a small compiler written in Rust that translates a subset of Shakva into C. A system C compiler builds the resulting program. Start with one Rust crate. Extend the subset when a concrete Shakva source file needs a feature and its behavior can be checked.

1. **Run [iterative Fibonacci](../examples/fibonacci.shk) end to end.** One command should translate the example to C, build it, and run it. For `n := 10`, the program must write `55` followed by a newline to standard output.
2. **Write the lexer and parser in Shakva.** Start with a lexer that stage0 can build. For a given input, check the tokens against an expected sequence. Repeat with the parser and expected syntax trees. Refine the grammar as these programs expose design choices.
3. **Execute the first Sylva bytecode.** Choose a small program, write its bytecode by hand, and run it on Sylva. Write a bytecode generator in Shakva, build it with stage0, and check that Sylva produces the same expected result from the generated bytecode.
4. **Compile the compiler to Sylva bytecode.** Extend the Shakva compiler and Sylva to cover the features used by the compiler itself. Build the compiler through stage0, then use that executable to compile its own Shakva sources. Check that the resulting compiler runs on Sylva.
5. **Rebuild on Sylva.** Run the bytecode compiler on Sylva against the same compiler sources. Run the rebuilt compiler on Sylva and check it against the same test cases. If generation is deterministic, compare the bytecode from the two builds byte for byte.
